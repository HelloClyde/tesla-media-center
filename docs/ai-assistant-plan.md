# 全局 AI 助手功能规划

记录日期：2026-09-24

状态：候选功能，暂缓实施。本分支仅保存设计，不代表已实现或已验证技术集成。用户明确暂不安排短期开发；恢复工作时先复核本文与项目现状。

## 目标与已确认方向

在应用左下角增加全局 AI 浮窗，在各页面均可唤起，跨页面保留对话。直接调用阿里云百炼上的通义千问模型，不接百炼智能体应用。模型决定使用哪个工具，工具由前端执行，结果回传模型完成多步对话。

不在本阶段实现功能、安装依赖或配置密钥。

## 界面方案

- 入口：44px 圆形 AI 按钮，位于左下角、导航栏右侧，避开导航和播放器操作区。
- 展开：向上打开聊天面板；在 773 × 601 可用区域中，初步采用约 360 × 420px，按实际空间收缩。此尺寸为设计起点，需实机验证。
- 顶部：AI 助手、新对话、收起。
- 内容：用户与助手消息、流式回复，以及“正在搜索”“找到结果”“已打开视频”等工具执行状态。
- 底部：输入框、发送、停止生成；失败可重试。
- 收起不丢失会话，页面切换不重建 Agent。第一版文字聊天，语音输入与播报后续考虑。
- 入口覆盖应用页面；未登录时可显示登录提示，模型调用仍须登录。浏览器原生全屏中浮窗是否可见，需结合 fullscreen 元素实现单独处理。

## 技术选型：优先评估 Vercel AI SDK

现有项目为 Vue 3 + Pinia + Vue Router，后端为 Flask，运行在 WSL/Linux。

候选方案使用 AI SDK 的 Vue 适配（`@ai-sdk/vue`）管理流式聊天状态，通过客户端工具调用处理程序执行工具并提交结果。Agent 编排由前端的会话状态、工具注册表和有限步数的续接流程共同完成。

此方案已基于官方文档完成初步调研，但尚未做集成原型。实施时须确认当前稳定版本、Vue API、浏览器兼容性、依赖体积，以及客户端工具自动续接的具体实现。不要直接照搬 React 示例或假设不同版本 API 相同。

### 职责分配

| 层级 | 职责 |
| --- | --- |
| 根组件中的全局浮窗 | 展示聊天、执行过程、输入和停止操作 |
| 前端 Agent / Pinia 会话 | 保存消息、接收工具请求、校验参数、执行工具、回传结果、控制最大轮数 |
| 前端工具注册表 | 描述工具及参数 schema，调用页面与播放器的真实方法 |
| Flask 模型接口 | 现有登录鉴权、保存密钥、转发千问请求、适配流式协议、超时和取消处理 |
| 百炼千问模型 | 生成文本回复或结构化工具调用 |

### 请求链路

```text
用户输入
  → 前端提交消息和允许使用的工具定义
  → Flask 鉴权并向百炼发送模型请求
  → Flask 将回复转换成 AI SDK 可消费的消息流
  → 前端收到完整工具调用，校验参数并执行
  → 将工具结果关联原 tool-call ID 回传
  → 继续模型请求，直至最终回复、达到轮数限制或用户停止
```

关键兼容点：百炼 OpenAI 兼容流不等同于 AI SDK UI 消息流，不能直接透传给默认聊天组件。优先在 Flask 适配；原型阶段评估转换工作量，必要时比较自定义前端 transport。暂不为此引入 Node 后端。

后端路径拟为 `/api/ai/chat`，配置包括服务地域对应的 Base URL、模型名称和后端环境变量 `DASHSCOPE_API_KEY`。模型与地域尚未确定，实施时以实际百炼账号为准。密钥不得进入前端包、浏览器存储或 Git；也不能通过现有通用配置读取接口返回给前端。

## 首批工具范围

以下是计划名称，不是现有可用接口：

| 工具 | 行为 |
| --- | --- |
| `navigate` | 打开允许的应用页面，通过 Vue Router 执行 |
| `searchVideos` | 调用现有 B 站搜索能力并展示结果 |
| `playVideo` | 播放指定搜索结果或已知视频 |
| `switchEpisode` | 切换当前播放器的分集 |
| `controlPlayback` | 暂停、继续、跳转进度、切换弹幕 |
| `getPageContext` | 获取当前页面、视频标题及播放进度等最小必要信息 |

工具调用已有业务方法，不靠 DOM 选择器模拟点击，也不执行模型返回的任意 JavaScript。页面挂载时注册工具，卸载时注销；切页后重新检查工具是否仍可用。涉及跨页操作时，先等待路由和目标播放器就绪，再执行。

第一版不加入车辆控制、付费、投币、退出账号等有额外影响的工具。后续增加此类工具时单独设计用户确认交互。

## 对话示例

用户：“帮我搜索周杰伦的视频。”

1. 千问生成 `searchVideos` 请求。
2. 前端搜索并展示真实结果，将有限条结果回传。
3. 助手总结结果，等待用户选中视频。
4. 用户指定某条结果后，前端执行 `playVideo` 并显示结果。

## 运行约束

- 校验工具名称与参数，只执行注册表中的工具；后端 API 继续执行正常鉴权，前端校验不能代替后端授权。
- 工具结果必须关联正确调用 ID；同一次调用避免重复执行。模型声明“已完成”之前应有实际执行结果。
- 流式工具参数接收完整并校验后才执行，不能把部分 JSON 当作完整指令。
- 限制上下文长度、工具结果体积和每轮任务最大调用次数；阈值在原型阶段确定。
- 停止按钮取消模型请求及可取消的工具任务，已执行的操作不能假装撤回。
- 搜索结果等外部内容按数据处理，不把其中的文本当作新的系统指令。
- 默认不自动上传车辆位置、账号凭据或完整页面内容；上下文只包含明确需要的信息。
- 恢复车机音频通道、麦克风/摄像头授权和部分播放操作受浏览器用户手势限制。AI 展示可点击操作按钮，由用户真实点击触发；不能承诺异步工具调用自动突破此限制。
- 收起浮窗与停止任务分开处理；刷新后的会话持久化策略尚待确定，首版可仅保留当前页面会话。

## 建议实施顺序

1. 复核当前主干、依赖版本及官方文档，确认百炼模型、地域和密钥配置方式。
2. 做最小技术原型：Vue 流式聊天 + Flask 协议适配 + 一个无副作用的前端工具，验证工具结果续接。
3. 加入全局浮窗及 Pinia 会话，验证切页、收起、停止与重试。
4. 接入页面导航和视频搜索工具。
5. 接入播放器状态及播放控制，处理页面生命周期和用户手势限制。
6. 在真实车机上验证尺寸、触摸操作、后台切换、音频焦点、全屏行为和模型响应速度。

## 验收要点

- 773 × 601 下浮窗不超出视口，不挡住核心导航，输入时能使用。
- 切换页面不丢对话；已卸载播放器的工具不会继续执行。
- 真实千问文本流、工具请求和工具结果回传可完成完整一轮；模拟测试不能替代真实联调。
- 无密钥、未登录、超时、断流、未知工具及非法参数均有明确提示。
- 用户停止后不继续发起新的模型轮次或工具调用。
- 页面与模型输出不会暴露 API Key。
- 原有播放、恢复声音和其他页面功能不退化。
