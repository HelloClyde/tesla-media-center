# App 地图数据与原生画面接入

2026-09-27。用户要求底图与导航统一采用 App 链路，不能把现有 Leaflet 网页瓦片称为 App 地图引擎。

## 已确认的边界

当前 TMC：App 5.1 路线协议 + 高德网页栅格瓦片 + Leaflet。没有调用网页 Key 加载器，但底图仍不是 App 地图数据解码/渲染链。

对固定版本 APK 17.00.0.2005 静态检查：

- `libmap_kit.so` 引用 `CreateVmapModule`。
- `libamapr.so` 包含 `GLMapEngine_nativeAttachSurfaceToRenderDevice`、`nativeBindMapEngineToRenderDevice`，并导入 EGL/OpenGL 绘制函数。
- `libamapdsl.so` 引用 `CreateVmapModule`、`getMapVectorTileInterface`，依赖原生地图视图生命周期。
- `libamapr.so` 包含 `MapTileDownloadManger`、`MapOnlineParseBmdTile`、`MapOnlineParseBmdTmc`、`MapOnlineParseMapConfig` 标识。
- 内嵌地图配置引用 `https://mps.amap.com/ws/mps/` 下的 `vmap`、`rtt`、`sdplus`、`smap`、`spot`。它们目前只是静态候选，尚未验证完整请求参数、认证、响应格式与各端点业务含义。
- `assets/vmap/` 有收藏图标资源与默认 GPS 模型，没有发现可直接替换 TMC 的网页地图组件。

可复现检查：

```sh
python tools/amap-app/inspect_map_engine.py .local-data/amap-app/amap-release.apk
```

脚本只读取文件并输出白名单依赖/路径；不输出签名材料，也不请求端点。出现一个 URL 不表示该接口可用。

## 两条实现路线

1. **App 数据移植到 Web**：复现地图请求和 BMD 等解码，转换成浏览器可渲染的数据，再实现地图样式、文字、图标、路况与导航覆盖物。需要 Web 渲染器；无法把 Android ARM64 `.so` 当成 WebAssembly 直接加载。该方案可以不常驻 Android。
2. **完整 App 原生画面**：在 Android 手机/虚拟环境运行 App，向 TMC 传输画面和触控。这样才真正复用原生渲染引擎，但持续依赖 Android 运行环境，并需要处理车辆定位传入、分辨率、时延、声音及生命周期。目前没有部署这个环境。

用户已选择第一条路线：App 地图数据解码后交给 Web 渲染，不采用 Android 画面串流。保留现有导航，待真实几何和显示验证通过后替换底图。

## 2026-09-27：BMD 传输验证

- 实际请求构造在 `libamapr.so` 的 `0x167b76c`；普通 BMD 使用 `/ws/render/bmd/tile`，不是配置 XML 中的旧 mps 路径。

## 地图磁盘缓存与设置（2026-09-27）

服务端以 SQLite 持久保存压缩后的完整地图块，键包含解码版本、级别和坐标。
默认有效期 168 小时，容量上限 512 MB（压缩数据容量，数据库另有少量管理开销）。
“设置与调试 → 地图缓存”可设 1–2160 小时、16–4096 MB，查看用量、保存策略及清空。
策略也持久保存；缩短有效期或容量后即时淘汰，之后在读写/查询用量时惰性清理。
优先淘汰最近最少访问的数据；失败或图层不完整的结果不写入磁盘。
清空保留策略，代次控制阻止清空前发出的请求重新填入旧结果。

默认本地目录 `.local-data/amap-cache`；Docker 默认 `/var/cache/tmc/amap`。
容器重启保留缓存；要跨镜像更新/容器重建保留缓存和设置，请添加命名卷：
`--mount type=volume,src=tmc-amap-cache,dst=/var/cache/tmc/amap`。
也可设置 `TMC_AMAP_CACHE_DIR` 指向可写持久目录。

缓存为当前服务器所有已登录用户共享，不是车机磁盘缓存。首次访问未缓存区域
仍需上游下载和解码；未包含样式/版本索引预热优化。前端保留短期显示缓存，
离开再进入地图页会从服务端重新获取，因此清空后重新进入地图即可验证。


地图 API 传输压缩：`/api/amap-app/map` 成功 JSON 响应大于 1 KiB 时，
按 `Accept-Encoding` 协商 gzip（显式 gzip;q=0 不压缩），仅在体积减少时使用。
设置 `Content-Encoding: gzip`、正确 Content-Length 与 Vary: Accept-Encoding，
浏览器自动解压，坐标和图层数据不变。不压缩媒体流或其他 API，也不重复压缩。
Network 中应对比 transferred（实际传输）与 resource size（解压后的大小）；
解压后仍显示几 MB 属正常现象。已登录响应设置 private/no-store，服务器磁盘
缓存仍负责复用地图数据，避免共享代理缓存认证响应。
