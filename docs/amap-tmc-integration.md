# 高德 App 地图导航接入

2026-09-27：已从旧的道路摘要实验页切换为地图导航。算路仍使用消费者 App 的接口，没有替换成开发者路线 API。

## 使用

访问 `/#/apps/amap`，底图为高德地图瓦片（Leaflet 显示，不需要网页 Key）。初始北京坐标明确标为示例。点击「定位」设置当前位置，选择「终点」后在地图点击选点，也可输入 GCJ-02 经度、纬度并回车。当前不含地址/POI 关键词搜索。

「规划路线」发出真实 App HTTP 请求，显示候选路线；选择方案后「开始导航」使用浏览器实时定位，提供位置跟随、剩余距离、转向提示、中文语音和偏航重算。「模拟导航」使用同一条真实算路结果回放，始终显示模拟标识，不读取车辆定位。

浏览器定位先通过 `coordtransform` 将 WGS-84 转为 GCJ-02。精度超过 60 米不推进引导；连续 3 次偏航且距离超过 40 米/1.5 倍精度时重算，重试间隔至少 20 秒。过期定位不处理，15 秒无新定位提示信号中断。退出或卸载页面会清理定位监听、回放/信号定时器、请求、地图与语音。

## 调用链

`AmapAppView.vue → POST /api/amap-app/route → 隔离 Python 子进程 → /ws/mapapi/navigation/auto/ (route_version=5.1) → 32 字节分帧 → Zstandard → Protobuf → 有界路线 DTO → Leaflet / 浏览器引导`。

原 `/probe` 路径保留兼容，使用同一新版解码器。`/status` 的 configured 仅表示本地资源可用。只有新版解码和几何检查通过才返回 ready/navigationAvailable。

- APK 17.00.0.2005 的 `libamaptbt.so` getRouteVersion JNI 位于 0x4a8bd4，读取 0xcb863 的字符串 `5.1`；旧 Java 构造器的 `2.5.3` 只是默认值。
- `libassembly_kit.so` DrivePathCodecImpl 0x714e0 → 0x7124c / 0x71378 → DrivePBPathDecoder 0xb60c8，提供分帧与解压链证据。
- Protobuf 版本字段 51；逐段坐标为 zigzag 增量，每段首点重新起算，比例 3,600,000 单位/度。逐 link 的坐标索引和数量须完整覆盖所属段。
- 长度、压缩大小、坐标范围、起终点邻近关系、逐段连接差异、坐标覆盖和总距离交叉检查；未知或不一致结构拒绝导航。
- 上游部分路口留有连接间隙。保留分段、记录 breaks，不生成虚假连接线；超过 100 米的间隙拒绝。显示距离按已解码几何计算。转向优先使用已验证的主动作码；辅助动作码 6/7/8 分别提示中间/右侧/左侧岔路，未识别的动作才按相邻路段方位估算。该辅助动作定义也见[北斗 GNSS 标准表 A.5](https://m.beidou.gov.cn/zt/bdbz/202407/W020240718511922218152.pdf)。
- 签名材料仅在子进程内存中使用；固定 HTTPS 主机、禁用重定向、40 秒执行上限、响应 4 MiB 上限、解压 16 MiB 上限。前后端需要 TMC 登录且返回字段白名单过滤。

## 高速服务区提示

App 5.1 驾车路线的部分高速路段在 `segment.5` 内带设施名称；
`segment.5.4` 在实测路线中分别出现服务区和收费站名称。解码器只将
以“服务区”或“停车区”结尾的名称加入对应路段，收费站不算服务区。
杭州至上海、北京至天津、上海至南京三条真实路线分别识别出 3、2、6 个服务区。
导航中显示前方两个服务区，并在进入其标注路段前约 5 公里播报一次；
临近转向时暂缓服务区播报。

此路由响应没有提供服务区入口的精确坐标或充电、加油、厕所等设施清单。
页面显示的距离是该路段中点的估算值，并明确提示驾驶员留意道路标志；
语音不宣称精确入口距离。[高德专业导航 SDK 文档](https://lbs.amap.com/api/harmonyosnext-navi-sdk/guide/navigation-map/navi-info)
描述了可返回类型、名称、经纬度和距离的服务区回调，但当前网页导航
没有运行该 SDK，不能把它的字段等同于此路线响应。

## 验收与限制

- 新版真实 HTTP 样本：北京两组起终点和杭州一组；共 5 条候选路线，52/48/85/140/138 个坐标，全部完成解析与 link 覆盖检查。
- 本机浏览器实际完成：真实请求 → 地图折线 → 模拟车辆跟随 → 路口提示变化 → 到达目的地；检查 773×601 布局。
- 研究工具 52 项、后端 12 项、前端几何 4 项测试；类型检查和生产构建。
- 实时定位/偏航逻辑已接入，但当前机器未做特斯拉 GPS 路测。浏览器权限、定位精度、语音支持取决于车机。
- TMC 不运行 Android APK 进程，无法直接订阅它的事件总线。开始实时导航后，Python 后端使用同一路线会话请求 APK 的二次导航 `routeguide`，从原生 NCP 事件中解出连续限速区间和带速度数组的摄像头，再按路线里程在网页端产生与 `NaviEventTypeSpeedLimitSection`（452）和 `NaviEventTypeShowNaviCameraExt`（95）相同语义的状态变化。452 更新当前限速牌并触发持续超速提醒；95 显示前方固定／区间测速牌和语音。路线未匹配、定位不可信或二次请求失败时保留未知状态，不使用路况速度推定法定限速。车机实测的事件位置与发声仍待核对，其他原生能力也未完整复刻。
- 地图标志：规划路线中的红绿灯坐标在 2D／3D 使用 APK 地图引擎 `icons_10000` 图集提取的原版竖向三色灯，不再使用红色圆点或手绘灯牌；只有可信、未过期的前方实时相位才附加对应灯色的倒计时。原生 `routeguide` 摄像头的路线里程投影到路线几何，2D／3D 地图标志使用 APK `icons_10001` 图集的摄像头剪影和红圈，沿行进方向向右侧偏移 18 米；限速数字仍由导航提示展示，不再挂在地图图标下。事件缺失时不凭空添加测速标志，路侧偏移是当前显示规则，实际车机尺寸和遮挡仍需验收。

底图接口参考：[高德 TileLayer 文档](https://lbs.amap.com/api/maps-javascript-api/reference/layer/tilelayer)；显示层参考：[Leaflet API](https://leafletjs.com/reference.html)。

## 导航限速与测速事件（2026-10-03）

开始实时导航时，后端使用已规划路线会话向高德 App 的二次导航 `routeguide` 接口请求沿途扩展，解码带坐标的限速标志点并映射到路线进度。接近标志时，车机页面显示“前方限速标志”和距离；定位可信且附近没有更紧迫的转向播报时，使用现有导航语音播放提醒。二次请求失败不会阻止导航。

同一二次响应的 kind=3 NCP 数据另带限速区间和测速摄像头。杭州至嘉兴约 80 公里样本中，解出 21 段区间、66 个带速度的摄像头事件，以及上述 kind=2 的 43 个标志点。区间长度与 5.1 原生 link 长度逐段吻合；摄像头坐标和剩余里程也与路线几何相符。三类数据分别用于当前限速／超速提醒、前方测速提醒、前方标志提醒。首次动态导航请求只在开始导航时进行；请求失败不妨碍原有路线导航。车机上实际位置与播报仍需验证。

路况图层开关只影响拥堵线及其两分钟刷新；关闭路况不会清空或停止
限速、测速、限速标志及红绿灯事件。重新打开路况会恢复刷新并立即请求
一次最新状态。实时红绿灯请求只在当前位置与规划路线匹配、定位精度
不超过 25 米且融合引擎处于可信跟踪状态时发送；超过 10 秒没有可信
位置或进入隧道估算／恢复阶段时，页面隐藏实时灯色与绿波建议，避免
继续显示基于旧位置的倒计时。

## 路口放大图

路口放大图由 App 的 `new_vector_cross` 请求取得原始 JPEG 路面层与 PNG 箭头层。进入路口前 700 米开始请求，450 米内展示。原始响应明确缺少图片层时记为该路口无图；后端繁忙、网络错误或异常响应则在同一路口 20 秒后至多重试一次。离开路口、路线切换或页面卸载会取消待执行的重试，避免连续请求。

## 高德 App 路线拥堵（2026-10-03）

路线 5.1 响应中，每条 link 的交通状态直接对应 APK `RouteLink.getLinkTrafficStatus()` 的 `LinkStatus.status`。按 APK 的 `TMC_STATUS` 值，2 是缓行、3 是拥堵、4 是严重拥堵；0 是未知，1／16 是畅通。TMC 按原始 link 坐标范围绘制拥堵段，并在 2D／3D 导航及路线预览中保留相同颜色与进度裁剪。杭州与杭州至嘉兴的保存样本均解出拥堵段，不需要额外的 Web 交通态势 Key 或地图道路匹配。

开始实时导航后，每两分钟用同一高德 App 5.1 算路接口重新请求。只有 link ID 序列、路线坐标和长度都与当前导航路线吻合，才替换路况颜色；若高德改选另一条路线或请求失败，保留上次可靠的结果，待重新规划后再更新。该刷新会重新请求完整路线，目前没有解析 APK 增量 TMC 通道。原 Web 交通态势代理、路况 Key 设置和 45 秒轮询已移除。

导航现在同时保留 5.1 link 字段 5 的 `passTime`（秒），展示前方 2 公里内最近一段连续缓行／拥堵的预计通过时间和长度；进入该路段后改为预计剩余时间和剩余长度。2D、3D 与模拟导航共用这个提示，放在引导牌右侧、红绿灯提示下方。相邻颜色不同的拥堵段会合并提示，已驶过的路段会移除；同一拥堵段内各 link 速度不同，按各自的通过耗时与里程计算剩余时间，不按整段平均速度或本车当前速度猜测。耗时随原路况刷新更新；数据缺失时明确显示时间待更新。路线总览隐藏该提示。

## 导航 3D 视图（2026-10-03）

规划完成后，地点搜索自动折叠为目的地与“修改”入口；可以展开搜索并重新收起。选路总览按全部备选路线与起终点的共同范围缩放，避开顶部搜索、底部方案选择和右侧地图控件。各路线以不同颜色区分，选中路线放在共用路段的最上层。地图气泡展示方案编号、App 预计耗时与收费，点击气泡或路线可选择对应方案；气泡优先放在独立路段，必要时用引线连接并避让其他气泡。布局使用有限数量的路线采样点，仅在视口移动完成后更新，不参与导航跟车的逐帧渲染。

导航中的转向牌可点击或用键盘 Enter／空格进入路线全览；3D 导航暂时切为 2D 总览，返回后恢复原视角。每次进入从当前导航位置重新请求 App 算路以刷新备选方案、路况、耗时与收费，也提供手动“刷新路线”。全览固定当前剩余路线为蓝色、备选路线为灰色，地图气泡与底部方案卡片均可切换；定位、路线融合、播报及模拟播放继续运行。刷新本身不会替换正在使用的路线或原生导航事件会话：原路线单独保留，以剩余几何比较识别同一路线，不按不同会话中的数字 ID 判断；若刷新结果没有原路线，则保留原路线并显示实际返回的备选方案。原路线找不到对应新结果时，其剩余耗时仍使用原计划的里程比例估计。

选择备选路线时按车辆选择当下的位置与航向重新匹配，保留 GPS 监听和模拟计时器，切换到该方案原始响应中的 routeToken／routeIndex，重新加载红绿灯、车道、限速和路口图事件；原生索引不使用重排后的卡片序号。车辆已驶离候选路段或航向相反时提示刷新后再选，避免倒退至请求时的位置。刷新失败保留已有方案及当前导航，关闭全览、退出导航或路线会话变化时丢弃旧请求结果；地图缩放、拖动和面板尺寸变化只调整展示，不触发重复算路。

车机浏览器现将已解码的道路／建筑和 LNDS 瓦片写入 IndexedDB，2D 与 3D 先读取本机缓存，再向后端请求缺失瓦片；完整的 3D 建筑瓦片也可供 2D 使用。数据使用浏览器支持时的 gzip 压缩；缓存有效期默认 7 天、总量上限默认 1 GiB，设置范围为 16 MiB–8 GiB，单瓦片上限 64 MiB，并按最近使用时间淘汰。旧设置中的默认 96 MiB 自动升级，其他自定义容量保留。磁盘读取或解压超过 1.8 秒时先按缓存未命中继续加载，晚到结果仍可填充内存。设置页可修改本机缓存时间和容量，也可查看实际浏览器配额、站点用量、地图有效上限及清空；“申请长期保留”由用户点击后向浏览器申请。实际地图预算受浏览器配额约束，扣除同站点其他资源并预留 20% 配额；写入前淘汰，配额不足时再淘汰并重试一次。IndexedDB 不可用时仍走现有服务器缓存；扩大的是磁盘容量，解码内存窗口仍为八块。建筑保留 BMD 的轮廓、分段高度和导航专用日夜样式的五槽颜色及 APK 原版立面图片；圆形轮廓平滑处理。APK 的 `BUILDING_WINDOW` 着色器按高度混合底部色与顶部色，前端现复现这一步，不再把五槽误当作不同朝向的墙面。立面贴图的 UV 比例、楼层重复和其他颜色槽绑定仍是近似，详见 `docs/tesla-building-layer.md`。地标异步加载或切页后会释放几何、材质和贴图，避免大模型资源滞留。已核验的 LNDS FlatBuffer 边界表只有几何及未解释的数值，没有足以可靠区分虚实线、黄白线的样式字段，故继续使用中性色，不凭几何猜测交通标线语义。
